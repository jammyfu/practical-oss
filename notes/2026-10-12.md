# 近两年（2026-10-12）

每段从第一句直接念到最后一句。小标题不用念。

## 编辑、入口、稿和版本

### Helix

终端里写代码，不一定先花一个晚上给编辑器装插件。打开文件，颜色就有了，多处一起改也有了，语言服务能跳的定义也能跳。你要是用过 Vim 那种模态，手感是近的，但插件和脚本别想直接拿过来。近两年不少人干脆把它当成每天用的那个编辑器，远程机器上也是同一套。它不替你做版本管理，也不打算变成一个什么插件都有的大平台。许可是 MPL-2.0。改到它自己的源文件，这些改动要继续按这个许可公开。

### Envoy Gateway

集群的入口，以前经常是 Ingress 再加一串只有这家控制器才懂的注解。Ingress NGINX 到 2026 年 3 月就不再维护了，补丁也停了。入口还是要有人接。Envoy Gateway 用 Gateway API 把主机和路径写成正式对象，再交给 Envoy 去转发。2024 年它就到了 1.0。它不是唯一的接法，Cilium 和云厂商也有自己的实现。原来注解上的每一种花样，也不要假设都能原样找到替身。它管的是入口怎么配，不是指标存哪儿，也不是服务和服务之间那一层网格。许可是 Apache-2.0。仓库星标不高，不代表这事还没人在迁。

### Penpot

界面稿可以画在你自己开得了的工具里，布局用的就是网页那套 Flex 和 Grid。检查的时候能看到对应的标记，而不是只剩一层图层名字。2024 年 4 月的 2.0 把组件系统换了，又加上 CSS Grid，从那以后才比较常被拿来跟专有设计工具放在一起比。文件可以放在自己的服务器上，也可以用官方的站点。它不会把稿子变成已经上线的网站，代码仓库里的组件版本还是前端的事。许可是 MPL-2.0。官方另外卖 Enterprise，管的是组织和流程，设计平台这份源码还是开源的。字体和图片的版权，不跟工具一起变成你的。

### Jujutsu

Git 仓库可以留着，操作方式可以换一种。改动不用先放进暂存区，冲突了也能先记成一次提交，回头再解决，而不是把工作区卡在一半。同事没装这个工具也没关系，推上去的还是 Git 能看的提交。近两年换着试的人明显多了。命令是 jj，仓库叫 Jujutsu。书签这些上层信息不全在 Git 里面，只看分支的工具会看不见。它不提供代码托管和评审。Git 还是大家默认的那一套，这是旁边的一种用法。许可是 Apache-2.0。
