# 最新最热：口播稿

每条都按同一套说。先把结果扔到脸上，再用一个具体画面当钩子，接着说现在有多烦，然后把步骤收成一件今晚能做完的事。观众要的不是架构图，是「这东西到我手里，能变成什么」。

事实和许可证以 `entries/` 里的正文为准。这里只负责怎么说。n8n 的许可证不是开源许可，口播里不要把它说成开源软件。

## 本地把模型跑起来

### Ollama

能做成什么：自己的电脑变成一个只听本地的模型接口，编辑器和小脚本都能来问它。

结果先说。今晚这台电脑可以不把稿子发到别人的网站上，自己回答你。

钩子在这儿。你输入一行，模型就坐在本机，像多了一个不用开网页的同事。

痛点是，想试个模型，先得看懂一堆环境、显卡和文件格式，试一次就像搬家。

你也行。先只做一件事：让一个模型在本机开口。能开口之后，再把它接到你已经在用的编辑器上。Ollama 干的就是把「下载、运行、给个本地接口」收成这一件事。

### llama.cpp

能做成什么：一张普通显卡，甚至只有 CPU，也能把量化后的大模型跑完一次对话。

结果先说。模型不用先住进机房，才能回答你一个问题。

钩子是文件大小。同一颗模型，换成更小的量化版本，原来塞不进内存的，现在塞得进。

痛点是原始权重又大又挑环境，笔记本一打开就提示内存不够，人直接放弃。

你也行。不要先追最新最大的模型。先找一个允许你用的、已经量化好的小模型，让它在自己机器上答完三句话。llama.cpp 负责的是这次推理本身。权重能不能商用，要另看模型自己的许可。

## 少装一套工具

### uv

能做成什么：新的 Python 项目从「装对版本」到「依赖装完」，不用再拼三条老命令。

结果先说。你明天新建一个 Python 小工具，环境不用再求人看。

钩子是时间。别人还在等旧的安装转圈，你这边依赖已经就位，人可以开始写第一行。

痛点谁都遇到过。电脑上有三个 Python，项目要的是第四个。虚拟环境忘了激活，包装进了系统里，第二天换一台机器就复现不了。

你也行。只拿一个旧脚本做试验，用 uv 给它单独的环境和依赖。跑通这一个，以后新项目都按这一下。它把装包、虚拟环境和 Python 版本收进同一个程序。

### Ruff

能做成什么：保存之前，Python 文件的格式和一批低级错误会被同一次检查处理掉。

结果先说。你提交上去的代码，不用再为了引号和导入顺序被人打回来。

钩子很小。一个工具，原来要记三套命令的活，现在记一套。

痛点是检查工具各管一段。格式化过了，导入顺序又报错，报错修完，另一台电脑的版本还不一样。

你也行。先只对一个文件夹开检查，看到它标出的都是你认得的问题，再扩到整个仓库。Ruff 做的是 lint 和格式化，不替你设计功能。

### Bun

能做成什么：一个 JavaScript 小服务从安装依赖、跑起来到跑测试，不用先凑齐四套工具。

结果先说。今晚你可以让一个小接口在本机答你一次请求。

钩子是工具数量。运行、装包、打包、测试，常常是四个名字。这里先记一个。

痛点是新项目还没写业务，先在版本和配置上耗掉半小时。

你也行。拿一个只有一个文件的小接口试。它能响应，这条链路就通了。Bun 本体是 MIT，发行包里还链了别的许可组件，拿去分发安装包之前要看条目正文。

### Biome

能做成什么：前端项目保存时，格式和基本检查由同一次操作完成。

结果先说。团队不用再为了「这个括号谁改的」吵一版。

钩子是配置文件变少。格式化一套、检查又一套的日子，可以先收成一套。

痛点是新人第一天就在两份配置里迷路，改一行代码附赠三行无关格式。

你也行。先在一个新的小页面上用它格式化。看顺眼了，再替换旧项目里重叠的那一部分。

## 写代码的那扇窗

### Zed

能做成什么：两个人打开同一个项目，一起改，光标互相看得见。

结果先说。结对的时候，不用再把屏幕共享开成「你看我操作」。

钩子是速度。窗口是原生的，打字时不用先等一个网页壳醒过来。

痛点是远程看代码，一边共享桌面一边说「往下一点」。两人改同一处，还得传来传去。

你也行。先两个人同时打开一个练习仓库，改同一个文件，确认能看见对方的光标。Zed 把协作放进编辑器本身。许可证是 GPL，拿它做二次分发要先看条目。

### Ghostty

能做成什么：终端窗口本身变得顺滑，里面的命令一个都不用换。

结果先说。你的 shell、你的快捷键、你的仓库，都留在原地，换的只是那扇窗。

钩子是滚动和文字。长日志刷过去的时候，窗口还跟得上你的眼睛。

痛点是终端一多、字一密，旧窗口就开始拖，人以为是机器慢。

你也行。先只把一个常用项目的窗口换成它，命令照旧敲。顺了再换第二个。它是终端，不是一种新的命令语言。

### Astro

能做成什么：一篇文档或一个营销页先变成很快的静态页面，只有真正要动的那一块才带脚本。

结果先说。你的说明页可以先被打开，而不是先加载一整套应用。

钩子是体积。页面看起是网站，脚本只留在那个会交互的小组件上。

痛点是博客也用做后台的那套框架来写，打开一篇文章要等一堆用不上的代码。

你也行。先把一篇已经写好的说明搬进去，发出去能打开。交互以后再加一块。

### htmx

能做成什么：点一个按钮，只换页面上的一块，背后仍由服务器返回 HTML。

结果先说。一个老网页可以长出「点了就更新」的感觉，不用先重写成单页应用。

钩子就在按钮上。请求发出去，回来的是一块 HTML，放进原来的位置。

痛点是小功能也要先选框架、打包、管状态。一个筛选列表，工程先变大。

你也行。找页面上已经有的一块列表，让它按条件刷新自己。成了，你就知道这条路能走。整站架构不用当天推翻。

## 表格和日志

### DuckDB

能做成什么：一个 CSV 或 Parquet 不用先导入数据库，就能用 SQL 算出结果。

结果先说。今天下班前，你可以用一句 SQL 回答「这个表里谁最大」。

钩子是文件本身。表还躺在文件夹里，查询已经跑完。

痛点是为了一次统计去装数据库、建表、导入，问完问题，服务还丢在那儿。

你也行。拿一份你看得懂的导出表，只写一句按日期汇总。DuckDB 嵌在你当前的程序里，没有单独一台服务器要养。

### Polars

能做成什么：几十万行的表，在脚本里过滤、分组、汇总，不用先养成逐行循环的习惯。

结果先说。你那份每次打开都要等的表格处理脚本，可以先变短、变快。

钩子是写法。你描述要哪几列、怎么分组，引擎按列去算，而不是你自己写循环一行行搬。

痛点是数据一多，旧写法先卡在内存和等待上，人开始怀疑是不是该上大集群。

你也行。把一段「读入、筛选、求和」换成它。数字对得上，再换下一段。它适合中等规模的本地表，不是公司的数据仓库。

### ClickHouse

能做成什么：日志和事件可以按时间问「过去一小时哪种错误最多」，不用把业务主库问到卡住。

结果先说。线上出了状况，你有一个专门回答统计问题的库，业务库继续记账。

钩子是问法。按小时、按接口、按错误码，这种扫描聚合正是它吃的饭。

痛点是把日志往订单库里塞，一查报表，下单也跟着慢。

你也行。先只接一种日志，保留几天，做一张「错误最多的接口」的查询。能回答这一张，再加第二种。它是分析库，不拿来当唯一的账本。

## 放在自己机器上的产品

### Immich

能做成什么：手机新拍的照片备份到自己的机器上，用时间线翻，不先交给厂商相册。

结果先说。家里可以有一本自己的相册，人换手机，照片还在你的硬盘上。

钩子是翻照片的方式。时间线还在，只是服务器换成了你自己的。

痛点是空间要钱，隐私条款要人自己猜，哪天账号出问题，整本相册一起着急。

你也行。先备份一个相册，不要第一天就搬十年的照片。能从浏览器看到这批，再开自动备份。磁盘和异地拷贝要自己留，软件不替你保证硬盘永不坏。

### Jellyfin

能做成什么：自己的电影和剧集在浏览器或电视上按海报墙播放，观看记录留在自己这边。

结果先说。客厅可以有一个不绑厂商账号的片库。

钩子是海报墙。文件还是那些文件，打开之后像一个你自己的播放站。

痛点是片子散在硬盘各处，找一集要翻文件夹，换个设备进度就丢了。

你也行。先放进两部你有权播放的片子，在浏览器里播完一集。能续播，再整理剩下的。它不提供片源。

### Home Assistant

能做成什么：灯、传感器和开关按你写的条件动作，核心逻辑跑在自己家里，不经过每一家的云。

结果先说。你进门，灯可以按你定的条件亮，规则写在你家的机器上。

钩子很小。一个门磁，一盏灯，一条「打开就亮」的自动化。

痛点是每个电器一个 App，离家之后才发现规则都押在别人的服务器上。

你也行。只接一个你已经买到的、它支持的设备，做成一条自动化。成功了再加第二个。不要第一天就改造全屋。

### PocketBase

能做成什么：一个小工具拥有注册、存数据和上传文件，后端就是一个可执行文件。

结果先说。你的小想法可以有用户和记录，不用先租一整套后端平台。

钩子是数量。数据库、登录、文件，这次先记成一个程序。

痛点是做一个给十个人用的登记页，也要先摆开服务器、数据库、鉴权三套东西。

你也行。做一个只记录「名字和一条备注」的页面，自己注册一个用户，存进一条数据。这条通了，再加文件或权限。它适合小应用，不是大型多团队平台。

### n8n

能做成什么：一个表单提交、一条定时任务、一次接口调用，可以在画面上串成一条会自己跑的流程。

结果先说。每天手工复制的那一下，可以变成到点自己发生。

钩子是节点。左边一个触发，右边一个动作，中间不用先写完整的服务。

痛点是数据从表格到通知，人在中间当搬运工，周末也得盯着。

你也行。只自动化一件你每周都做的搬运：到点取一处数据，发到另一处。跑通一次再加分支。n8n 很常用，但当前许可证是 Sustainable Use License，不是开源许可。口播和简介里都要说清这一点，不能讲成「一个开源自动化神器」。

## 把模型做成服务

### vLLM

能做成什么：一张或多张 GPU 同时接住很多人的提问，而不是一次只耐心地答一个。

结果先说。你的模型可以变成一个接口，别的程序排队来问，机器不会被一个一个的对话浪费掉。

钩子是同时。十个人一起问，它想办法把这些请求拼在同一张卡上算。

痛点是笔记本上能聊，一放到给同事用，显存和等待就一起爆。每个人独占一次推理，卡都空转。

你也行。先用一个已经允许你部署的模型，开一个只有自己会调用的接口，连续问它五句，看响应还在。vLLM 负责的是这次服务的吞吐。模型权重的许可仍然另算。

### ComfyUI

能做成什么：一张图从「选模型、出图、放大、再改一版」可以存成一张节点图，下次换词就能再跑。

结果先说。你满意的那套出图步骤，不用只存在脑子里。

钩子是线。每个方块做一步，线接上下一步。改其中一格，整条流程还在。

痛点是脚本一改就忘了上次哪几个参数好看。想复现，只能翻聊天记录。

你也行。先跑通一条最简单的「提示词进、图出」。图能出来，再加放大或改图。它不赠送模型，模型能不能用要看你下载的那一份。软件本身是 GPL-3.0。

### Open WebUI

能做成什么：本地模型前面多一个网页，可以登录、可以换着聊，家里其他人不用先学命令行。

结果先说。模型已经在你电脑上跑了之后，家人打开浏览器就能问。

钩子是入口。后面仍是你自己的模型接口，前面变成一个聊天页。

痛点是命令行只有你会用。人一多，每个人都来问你「那个窗口怎么开」。

你也行。先只把自己的账号配上一个已经在本地跑着的模型，问成功一句。再考虑要不要开给第二个人。这个界面现在的许可证不是开源许可，源码能看，品牌和用户规模上还有额外限制。口播里别把它讲成开源聊天神器。

### Dify

能做成什么：一份资料加上一个模型，变成一个按步骤回答的小应用，步骤在画面上看得见。

结果先说。你可以把「先查资料、再按这个格式回答」做成一个别人打得开的入口。

钩子是工作流。检索是一格，模型是一格，输出格式是一格，不用把整件事写成一个大脚本。

痛点是演示时模型很会说，一碰到你自己的文档就胡编，过程也没法给同事看。

你也行。先上传一份短资料，做一条只有三步的流程：接收问题、查出相关段、按固定格式回答。答对这一份，再加长文档。Dify 使用很广，但现行许可是改过的 Apache 条款，带多租户和品牌限制，不能说成 Apache-2.0 开源软件。

## 怎么继续拍

一条片只讲一个「能做成什么」。开头三秒就是结果，中间用观众这周真的会遇到的烦，结尾停在最小的那一件事上。功能细节留给条目正文，口播里不背命令。
