## 它解决什么问题

一份代码会被很多人改，也会被同一个人改出好几条试验线。没有历史记录时，只能靠压缩包文件名猜哪一版能用。Git 把每一次提交变成可回溯的快照，并让分支、合并和远程同步成为日常动作，而不是临时拷贝目录。

## 核心功能

- 本地提交、分支、标签和合并。历史存在本机仓库里，断网也能查看和提交。
- 与远程仓库同步。`clone`、`fetch`、`pull`、`push` 把一份历史分发到 GitHub、GitLab 或自建服务器。
- 对比与追溯。可以看某次提交改了什么，也可以查某一行是谁在什么时候引入的。
- 暂存区。改动可以分成几次提交，而不是「当前目录和上次备份之间的全部差异」一次交上去。

## 通常怎么用

几乎所有现代软件协作都从 `git clone` 开始。个人用它保留试验分支；团队用它配合拉取请求做代码审查；发布系统用标签标记可部署版本。GitHub 和 GitLab 提供的是托管和审查界面，底层历史格式仍然是 Git。

## 它不负责什么

Git 不保管议题、不跑测试、也不规定分支策略。大二进制文件会让仓库膨胀，那种情况通常另加 Git LFS 或把产物放到对象存储。它也不理解某种语言的项目结构，构建和依赖管理是别的工具的事。

## 许可与热度

Git 本体以 GPL-2.0 发布。GitHub 上的 `git/git` 是镜像，2026-10-10 的星标是 63,766，这个数字远小于它在行业里的实际地位。贡献走邮件列表和项目自己的补丁流程，而不是普通的 GitHub 拉取请求。
