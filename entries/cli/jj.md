## 它解决什么问题

Git 能用，但暂存区、分支名和冲突经常把一次小改动变成一串补救命令。改到一半冲突了，工作区就停在一个不能提交的状态。Jujutsu 仍然把提交和文件放在 Git 仓库里，这样现有的托管和工具还能用，但操作模型换成：改动自动记下来，冲突是历史里的一种状态，而不是必须马上清掉的现场。

## 核心功能

- 以 Git 为存储。提交和文件在 Git 仓库里，多数 Git 托管可以直接配合。
- 没有暂存区。工作区里的修改就是下一次要记录的内容，少一层「先加进索引」。
- 冲突可以留下来。冲突写进提交，之后再解决，不必把仓库停在冲突中间。
- 用 revset 选择提交，用书签指向要推上去的位置。书签这类元数据不完全等同于 Git 分支。

## 通常怎么用

已经有 Git 仓库、又经常在变基和冲突上耗时间的人，会在同一份仓库旁用 `jj` 工作，需要给还没用它的同事时再以 Git 的形式推送。新的个人项目也会直接从它开始。团队的代码评审、权限和持续集成仍然在原来的 Git 托管上，不会因为换了客户端就换掉。

## 它不负责什么

Jujutsu 不是 Git 的又一个子命令集，键位和概念都要重新学。书签和其他上层信息默认不全部放进 Git，只看 Git 分支的工具会看不到这些状态。它也不提供代码托管、评审和权限。Mercurial 等其他存储还不是现在日常使用的那一层。Git 本身仍是行业默认，这个工具是旁边多出来的一种用法。
