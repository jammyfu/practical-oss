## 它解决什么问题

主流图形编辑器把界面放在浏览器内核里，输入延迟和内存占用跟着整页应用走。多人一起改代码时，协作又常常是另装的插件或屏幕共享，和编辑器不是一件事。Zed 用 Rust 做原生编辑器，界面由自己的 GPU 框架绘制，并把实时协作放进编辑流程里。项目来自 Atom 和 Tree-sitter 的作者。

## 核心功能

- 多线程编辑核心和 GPU 界面。大文件、多光标和频繁诊断时，尽量不让界面卡住。
- 内置协作。频道里可以共享项目、跟着对方的光标，一起改同一块缓冲区。
- 语言服务、诊断、内嵌终端和 Vim 风格的按键模式。
- 用 Tree-sitter 做语法树和语法高亮，扩展用来补语言和工具，而不是重写编辑器。

## 通常怎么用

把它当作日常写代码的图形编辑器，用来替代以扩展市场为中心的编辑器。结对或远程一起改同一处时，开编辑器里的频道，而不是另开会议软件共享屏幕。语言智能仍依赖各语言自己的语言服务。不想维护一套原生编辑器、又重度依赖某个专有扩展时，继续用原来的编辑器更省事。

## 它不负责什么

它不托管 Git 远程，也不跑持续集成和代码评审。协作解决的是「现在一起改」，不是合并请求和权限模型。扩展数量不能和历史更长的编辑器市场比。界面框架可以单独拿去写别的桌面程序，但那不是使用编辑器的人要做的事。账号和托管协作如果走官方服务，和「把源码编出来」不是同一件事。
